# web-chat（本轮变更的部分）

本文件只声明本次变更对 Web 控制台对话渲染的**修改**。phase-16 仍然是一次回答"按步骤渲染"
这件事的历史记录；下面是它之后的行为变化。

## MODIFIED Requirements

### 需求：一轮结束后的过程默认折叠

phase-16 的折叠规则是"只折叠每一步的工具卡片，思考始终留在流里"（见
`openspec/changes/phase-16-turn-steps/specs/web-chat/spec.md` 的「折叠规则」与「摘要行」）。
现在改为：**整轮的过程（步骤 + 思考）作为一个块，在轮次结束后默认收起**，读者看到的是
一行计数加下面的答案。

理由：一轮长任务的思考与工具往返加起来可以占掉几屏，把它压在答案上方意味着读者每次回来
都要先滚过自己已经读过（或本来就不需要读）的过程。折叠把"结果"变成默认视图，"过程"变成
一次点击能得到的东西——而不是反过来。

- 折叠行（有步骤时才存在）：`执行过程` + `N 次工具调用` + `M 条消息`，外加失败标记
  （任一步有失败调用）与工具合计耗时（没有任何调用报耗时则不显示）。
  - `M 条消息` = 这一轮的步骤数 —— 一次 ReAct 迭代就是一条与模型交换的 assistant 消息。
  - 两个计数与展开后能看到的内容**同口径**：`ask_user` 渲染为卡片而不是工具行，因此不计入
    `N`；悬停提示里写明这两个口径，因为"消息"这个词本身有歧义。
  - 计数用等宽 + `tabular-nums`：数字每次变化时这一行不能左右抖。
- 折叠规则（`steps.js` 的 `processShouldBeOpen`）：轮次进行中展开，轮次结束（收到答案、
  失败、被停止）折叠；读者点过之后由读者说了算（`pinned`），且**读者在流式期间点开的话，
  答案落地后不会被自动收起**。
  - 判据是"这一轮还在不在跑"，**不是**"有没有出现文字"：步骤的正文在 `step_end` 会被清空，
    用后者会让过程在一轮里反复折叠又展开。
  - 折叠是**派生的**，不持久化：刷新页面后新的一轮（已经结束）自然又是收起的。
- 折叠时不渲染过程本体：步骤行、思考、工具卡片都不在 DOM 里（不是 `display:none`），
  所以一个二十步的轮次在收起状态下不会留下任何 DOM 重量。
- 展开后与 phase-16 一致：每步一行（`#N` + 工具名摘要 + 失败标记 + 工具耗时），步内先思考
  后工具卡片，工具卡片**仍各自折叠**（长轮次里卡片才是体积的大头，两层折叠各管一件事：
  第一层管"要不要看过程"，第二层管"哪一步的参数与结果要看"）。
- 答案始终在过程之外、之下，且从不折叠。
- 没有步骤的轮次（模型直接回答、或只调用了 `ask_user`）不渲染折叠行——一个"0 次工具调用"
  的控制行只是噪音。

### 需求：这一轮的计划在下一件工作开始时清掉

计划（`chat_plans`）跟着一次请求走。用户发来新消息时，如果现有计划已经**全部完成**
（所有任务 `done` 或 `skipped`），服务端在开跑前删除它并在新一轮的事件流里广播一个空计划，
所有打开着的页面立刻收起任务看板；客户端的 `sendMessage` 也先本地清一次，让看板在点发送
的瞬间消失。

还有未完成项的计划**不清**：它是「继续执行」的接续点。「继续执行」本身也不清（那正是它要
继续的那份计划）。详见 `specs/task-plan/spec.md`。

## 边界

- 不改动 `step` 的粒度、SSE 事件、落库结构：这次变的只是"过程什么时候可见"。
- 不记住折叠状态（不写 localStorage、不写库）：一轮结束就该收起，与读者上次怎么点无关。
