# web-chat（增量）：一轮回答按步骤展示与保存

一轮助手消息不再只是「答案 + 一堆工具调用 + 一段思考」，而是「答案 + 一串步骤」：每个步骤
是同一次模型调用的思考、它说出口的过程性文字，以及它触发的工具调用。控制台按这个结构交替
渲染，并在答案出来后把步骤折叠起来。

其余契约（端点、事件之外的字段、附件、ask_user、预算、统计）不变。

## 数据

### `chat_messages.steps`（migration 13）

新增一列，与 `tool_calls` / `usage` / `attachments` 同构的 JSON 字符串：

```json
[
  {
    "index": 1,
    "reasoning": "先看看目录里有什么",
    "text": "我先列一下目录。",
    "tools": [
      {"id": "call_1", "name": "list_dir", "args": "{}", "result": "...", "err": "", "duration_ms": 12, "step": 1}
    ]
  }
]
```

- `index` 从 1 开始，按步骤递增；一轮里步骤是有序的。
- `reasoning` 是该步模型吐出的思考（可能为空：非推理模型）。
- `text` 是该步模型说出口的文字。**最后一步的 `text` 就是答案**，中间步骤的 `text` 是过程。
- `tools` 是该步触发的工具调用，字段与 `tool_calls` 里的元素一致（多一个 `step`）。
- 空串表示没有步骤信息（本次变更之前的行，或不需要分步的轮次），客户端必须容忍并退化。

### 兼容

- `reasoning` 与 `tool_calls` **继续照写**：审计、统计（`session_stats`）、以及尚未升级的
  客户端都还在读它们。`reasoning` 仍是整轮思考的拼接。
- 旧行（`steps` 为空）由客户端从 `tool_calls` + `reasoning` 重建：整轮作为一个折叠块，思考
  与全部工具卡片都在里面。历史会话只会**更好看**，不会显示不出内容。

## 事件

### `step_end`（新增）

一次模型调用结束、进入工具执行之前发出：

```json
{"type": "step_end", "step": 2, "text": "我先看一下配置文件。"}
```

- `text` 是该步已经产生的文字（可能为空）。
- 客户端据此把这一步的文字标记为**过程文字**：它不再进入答案区，而是留在该步里。
- 一轮的最后一步不会发 `step_end`（它没有工具要跑），它的文字就是 `done` 携带的答案。
- 老客户端收到未知类型走 `default` 分支忽略，事件流不需要版本协商。

## 服务端

- `chat.ToolRun` 增加 `step` 与 `json`（模型原始入参字符串）；`chat.Step` 描述一步；
  `chat.Result.Plan` 携带整轮的步骤（字段名避开已有的 `Result.Steps`，那是步数计数）。
- `turnAccumulator` 按事件的 `step` 归并：`step_start` 开一步，`reasoning_delta` / `text_delta` /
  `tool_call` / `tool_result` 落到当前步；`step_end` 把该步文字定稿。
- `persistTurn` 额外写 `steps` 列。**被停止的轮次同样写**：半途而止的一轮，过程正是要看的
  东西，而且每一步的 `reasoning` 不会重复（每步只属于它自己）。
- 工具调用若落在当前步之外（事件缺失 `step`），归入最近打开的步骤；没有任何步骤时归入第 1 步。

## 控制台

- **渲染顺序**：步骤块（每步一行摘要，可折叠）在上，答案在下，其后是错误条 / 预算提示 /
  token 页脚。步骤块与答案之间是「过程」与「结果」的分界。
- **折叠规则**：
  - 一轮进行中：当前步骤展开，历史步骤保持用户选择；第一个 `step_start` 之后到达的步骤默认
    展开。
  - 一旦该轮的答案开始出现在最后一步，自动折叠所有**未被用户手动操作过**的步骤。
  - 用户点过的步骤（展开或折叠）在整轮内不再被自动改动。
- **摘要行**：`步骤 N` + 该步工具名（最多三个，多则「等 K 个」）+ 失败标记 + 展开时长的
  工具耗时；展开后先渲染该步思考（Markdown，小字号），再渲染该步的工具卡片（沿用现有的
  参数预览 / 展开查看参数与结果 / 状态 / 耗时）。
- **默认状态**：整轮结束后，`steps` 里没有任何工具调用的轮次（模型直接回答）不渲染步骤块，
  只显示答案。
- `ask_user` 卡片、附件、复制、链路按钮、预算提示的位置与行为不变。

## 不在本次范围

- 不改动 `step` 的语义与粒度和 ReAct 循环本身（一步 = 一次模型调用 + 它触发的工具）。
- 不把步骤信息回放给模型（`reasoning` / 工具元数据仍然是展示专用的）。
