# Phase 16 — 一轮回答按「步骤」展示与保存

## Summary

服务端早就按**步骤**（ReAct 的一次模型调用 + 它触发的工具）产出事件，事件里也一直带着
`step` 字段，但落库时把这一轮折成了两堆：所有思考拼成一个 `reasoning` 字符串，所有工具调用
排成一个 `tool_calls` 数组。于是控制台只能渲染出「上面几十个工具卡片，下面一大段不分段的
思考」，两者无法对应，也看不出模型每一步想干什么。

本次变更把「一条助手消息 = 答案 + 一串步骤」写进数据契约：

- 新增 `chat_messages.steps` 列，存 `[{index, reasoning, text, tools[]}]`：每一步的思考、
  该步已经说出口的话、以及它触发的工具调用（含参数、结果、错误、耗时）。
- SSE 事件增加一个 `step_end`，让客户端在流式期间就知道某一步说完了（那点文字是过程而不是
  答案）。
- 控制台改为**按步骤交替渲染**：流式时一步步出现「思考 → 工具 → 观察」；这一轮出结果后，
  所有步骤自动折叠成几行摘要，答案独占正文；点任意一行即可展开该步的思考与工具详情。
- 老数据（`steps` 为空）按原来的两个字段退化重建，历史会话显示不变差。

## Why

- **可见性**：用户要的是「看出大模型每一步想干什么」。把步骤边界丢掉再展示，等于让读者自己
  在几十张卡片和一大段文字之间做对齐 —— 而那份对齐信息在落库那一刻就被扔掉了。
- **答案与过程分离**：ReAct 循环里模型常常先写一句「我先读一下这个文件」再调工具。以前这种
  过程性文字会和最终答案拼在一起，复制出来的回答混着过程。按步骤存储后，最后一步的文字才是
  答案，中间步骤的文字归入该步。
- **落库即真相**：只在浏览器里做分组是不够的 —— 刷新、换设备、别的客户端读同一条会话都得
  看到同样的结构，所以结构必须落库，而不是渲染时猜。
- **折叠不等于隐藏**：过程默认折叠，但每步都留一行摘要在正文之上，需要时一键展开；这样既
  「直接看到最后结果」，又随时能下钻到过程。

## What Changes

### ADDED

1. **`internal/store` — `chat_messages.steps`（migration 13）**
   - `ChatMessage.Steps`（JSON 字符串），与 `ToolCalls` / `UsageJSON` / `Attachments` 同构：
     文本列、由客户端防御式解析、空串表示「没有步骤信息」。
   - `AppendChatMessage` / `ListChatMessages` 读写该列。

2. **`internal/chat` — 步骤是消息的一部分**
   - `ToolRun.Step`：这次工具调用属于第几步（1 起）。零值表示未知（老数据）。
   - `ToolRun.JSON`：模型原始入参，落库后 `args` 列里那份是**字符串化**的（参数面板要渲染），
     需要它的地方用这个字段。
   - `Step`：`{index, reasoning, text, tools[]}`。
   - `Result.Steps`：本轮每一步的内容。
   - 新事件 `EventStepEnd`（`step_end`）：一步的模型调用结束，携带该步已产生的文字。客户端
     据此把「过程文字」与「答案」分开。

3. **`internal/server` — 落库与回放**
   - `turnAccumulator` 按 `step` 归并事件：`step_start` 开一步，`reasoning_delta` / `text_delta` /
     `tool_call` / `tool_result` 落到当前步。
   - `persistTurn` 多写一列 `steps`；`reasoning` 与 `tool_calls` 仍然照写（老客户端、审计与
     统计都还在读它们）。
   - 停止/失败路径同样保留已完成步骤 —— 半途中止的一轮，过程是最该看见的部分。

4. **`web` — 按步骤交替渲染**
   - `src/steps.js`：把持久化的 `steps` JSON 归一成渲染模型；`steps` 为空时从
     `tool_calls` + `reasoning` 重建（每个工具一步，思考挂在该错误…见 spec）。
   - chatStore：一轮的开始就建一个 `steps` 数组，事件按 `step` 写进对应步骤；`step_end`
     把该步文字移交为过程。
   - `ChatMessage.vue`：正文 = 最后一步的文字（答案）；其上每一步一行可折叠摘要
     （步骤序号 + 工具名 + 状态），展开后先看思考（Markdown）、再看这一轮的工具卡片。
   - 流式期间步骤默认展开、答案落地后自动折叠（用户手动点过的步骤不再被自动改动）。

### CHANGED

- `Result.Reasoning` 语义不变（整轮思考的拼接，供老消费者与统计用），但不再是 UI 的唯一来源。
- 答案的判定从「所有 text_delta 拼起来」改为「最后一步的文字」，中间步骤的文字归入该步。

### REMOVED

- 无。旧的 `reasoning` / `tool_calls` 列继续写入，老会话继续可读。

## Impact

- 迁移 13 是纯 `ALTER TABLE ADD COLUMN`，向后兼容；旧行 `steps` 为空，前端退化重建。
- 没有新的配置项，没有新的端点，事件流只增加一种类型（老客户端忽略未知类型，已有 `default`
  分支）。
