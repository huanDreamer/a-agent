# Phase 9 — 工作区：会话的目录边界

## Summary

工作区是一个**本地目录**，同时是左侧会话列表里的**一层文件夹**：

1. **一个工作区 = 一个真实目录**。新建时在控制台里浏览本机目录并选中一个，不自动创建目录。
2. **每个会话都属于某个工作区**，会话列表按工作区分组显示（像文件夹）。
3. **工作区在侧边栏直接管理**：重命名、删除、在其中新建会话。
4. **工作区不带策略**。`read_only` / `enable_bash` / 限额仍是全局的 `tools.*`；
   一次性给工作区加策略的尝试（本次变更的前一版）已撤销 —— 它是两个概念混在一起。
5. 飞书渠道仍可用 `/workspace` 与自然语言切换，并且**真正在这个目录里干活**
   （`internal/chat.Runner` 工具循环）。

隔离的本质是**路径限制级**（沿用 `internal/workspace` 的沙箱语义），不是容器级隔离：
`bash` 仍可访问工作区外的绝对路径。这一点在 UI 与文档里明确写出。

## Why

- **只有一个工作区，等于 agent 只能碰一个项目。** 之前 `tools.workspace` 是进程级单例，
  换项目要改配置 + 重启。
- **工作区是「在哪个目录里干活」，不是「能干哪些事」。** 前一版给它加了
  `read_only` / `enable_bash` / 描述 / 生效工具列表，结果是：设置页要有一整套策略与工具
  管理，而用户真正想要的只是「把这些会话放进那个目录」。策略回到全局配置，工作区只剩
  一个属性：目录。
- **会话列表需要一层组织。** 会话多了以后，按工作区分组是唯一能一眼看懂「这条对话在哪个
  项目里」的排列方式 —— 而它也正是切换工作区最自然的位置。
- **目录要真实存在**。自动在 `workspaces_dir` 下建空目录，agent 面对的是一个空文件夹；
  而用户想要的是「让 agent 去写我那个已有项目」。因此新建工作区 = **选一个已存在的本地目录**。

## What Changes

### ADDED

1. **工作区 = 目录**（`internal/workspaces` 重写）
   - `Spec{Name, Root, SessionCount, CreatedAt, UpdatedAt}`；没有策略字段。
   - `Create(root, name)`：`root` 必须是**已存在的目录**（解析符号链接后校验，拒绝文件、
     不存在的路径、以及文件系统根 `/`）；`name` 缺省取目录名，仅作标签。
   - `Rename(old, new)`：只改标签，目录不动；重命名在同一事务里同步更新 scope 绑定。
   - `Delete(name)`：**永不删除文件**；把该工作区里的会话迁到另一个工作区（只剩一个时拒绝删除），
     并在返回里说明迁到了哪里。
   - `EnsureSeed`：表为空时用 `tools.workspace`（或进程工作目录）建一个初始工作区，
     并把没有任何绑定的历史会话绑到它 —— 这样「每个会话都属于一个工作区」对旧数据也成立。
   - `Browse(path)`：列出某个目录下的子目录，供控制台选择目录；默认从用户主目录开始。
2. **`/api/fs/dirs`**：目录浏览接口（管理台已认证）。这是「选择本地目录」在浏览器里的
   唯一可行实现 —— `input[type=file]` 拿不到服务端绝对路径。
3. **侧边栏工作区分组**（`web/src/components/AppSidebar.vue`）
   - 每个工作区一个可折叠分组，组内是它的会话；分组头显示目录名与完整路径（title）。
   - 分组头悬停出现：新建会话（在该工作区里）、重命名、删除（两步确认，确认文案写明会话会被迁走）。
   - 「新建对话」按钮归属于当前展开/选中的工作区；没有任何工作区时引导先建一个。
   - 工作区重命名/删除后，分组与会话列表立即刷新。
4. **目录选择器**（新组件）：面包屑 + 上级目录 + 双击进入 + 「选择此目录」，
   由 `/api/fs/dirs` 驱动。
5. **会话创建/列表带工作区**：`POST /api/chat/sessions` 可带 `workspace`；
   `GET /api/chat/sessions` 每条会话带 `workspace`（SQL 层 join，不在前端拼）。
   `POST /api/workspaces` 由 `{name, root}` 创建，`PATCH /api/workspaces/:name` 重命名，
   `DELETE /api/workspaces/:name` 删除（迁移会话，拒绝删最后一个）。

### MODIFIED

- `internal/store`：migration 10 把 `workspaces` 收成 `name + root + 时间戳`
  （`description` / `read_only` / `enable_bash` 删除），`chat_sessions` 列表带上工作区。
- `cmd/huan-agent`：每轮按会话工作区绑定工具这件事保留；**去掉按工作区的策略摘除**，
  写工具与 `bash` 的开关回到全局 `tools.*`（与本次变更之前一致）。
- 飞书：`/workspace`、`/workspaces`、自然语言切换保留；回复只讲名字与目录（不再有策略行）。
- 文档：`docs/tools.md`、`docs/feishu.md`、`docs/admin.md`、`web/README.md`、`docs/status.html`。

### REMOVED

- 设置 → **工作区** 分区整页（工作区策略、生效工具、描述编辑、按名字自动建目录）。
- `tools.workspaces_dir`（不再自动创建目录；工作区指向已有目录）。
- 每工作区的 `read_only` / `enable_bash` / 描述 / 生效工具接口字段。
- 内置 `default` 工作区（改为首次启动时种下的真实工作区，可重命名、可删除）。

## Non-goals

- 容器、namespace、seccomp：工作区之间的隔离是路径级的，`bash` 仍可越界访问绝对路径。
- 会话在多工作区之间拖拽移动（本版用会话头部的工作区选择器切换）。
- 工作区级别的模型 / 技能 / 记忆配置。
- 版本控制集成、模板、依赖初始化。
- 在浏览器里新建目录（只选择已存在的目录）。

## Risks

| 风险 | 缓解 |
| --- | --- |
| 目录浏览接口会暴露本机目录结构 | 与既有工具同一威胁模型（控制台本来就能让 agent 读写命令）；`docs/admin.md` 安全章节写明，并建议公网部署开启登录校验 |
| 工作区指向 `/`、`$HOME` 这类大目录 | 拒绝文件系统根；其余允许（用户是显式选择的），文档提示 |
| 删除工作区会「丢掉」会话 | 会话不删除，迁移到另一个工作区；只剩一个工作区时拒绝删除；确认文案写明 |
| 旧数据里的会话没有工作区 | `EnsureSeed` 打底并回填绑定；列表接口用 join，读不到时按种子工作区兜底 |
