# capability: background-jobs（本阶段增量：归属与会话内可见性）

## 目标

让一个后台进程**属于启动它的那次对话**，并且在那次对话里就能被看见、被看日志、被停止 ——
而不是藏在一个和它无关的设置页里。

## ADDED

1. **来源可追溯。**
   - `jobs.Spec` / `jobs.Job` 增加 `Scope string`：启动该作业的对话。取值与 runner 发布在
     turn context 上的 scope 一致（Web 会话 id 加前缀、飞书 open_id 加前缀）。
   - 工具层通过 `BackgroundPolicy.Scope func(ctx) string` 读取，不 import `internal/chat`。
     nil 或返回空串一律视为"无会话"：CLI 场景合法，且读者必须把"无 scope"当成一个真实状态。
2. **列表接口能按会话分组。**
   - `GET /api/jobs?session=<id>` 在响应里增加 `scope` 字段（该会话作业记录的 key）。
   - 不带 `session` 时**不得**出现 `scope` 字段：客户端按它分组，"缺失"和"空"不能是同一件事。
   - 作业列表本身仍是本进程的全部作业：一次请求同时服务"本会话"和"同工作区其他会话"两组。
3. **会话内可见性（控制台）。**
   - 对话标题栏渲染一个 chip：本会话有运行中的作业时显示运行计数，只有历史记录时显示记录数，
     本会话为空但同工作区有作业在跑时显示"同工作区 N 个后台进程"；没有任何相关作业时不渲染。
   - 点击 chip 打开右侧抽屉：**本会话**的作业在前（运行中的排最前），**同一工作区的其他会话**的
     作业在后，后者明确标注来源。
   - 抽屉里能做旧面板能做的一切：看列表、跟随日志、停止、删除记录；日志窗口的
     `dropped_bytes` / `skipped_bytes` / `log_capped` / `output_open` 如实呈现。
4. **一个轮询器。**
   - 计数与列表读同一份状态，不允许出现两个独立轮询（同一秒两个答案、停止在飞时状态不一致）。
   - 轮询只在**存在运行中的作业**时进行；"新作业出现"由聊天流里的作业工具结果触发刷新。

## REMOVED

- 设置 → 后台进程子页。它能看到的内容（同一进程的全部作业）现在在会话抽屉的第二个分组里，
  并且带上"哪个会话起的"。

## 边界与不变式

- `bash_jobs` 的语义**不变**：仍然只列本工作区的作业，别的会话在同一工作区起的进程对模型
  不可见也不可管理。控制台看到更多，是因为它是给操作者的。
- 会话归属**不延长生命周期**：作业仍在 agent 进程退出时统一终止。
- scope 是分组键，不是权限：`/api/jobs` 仍返回本进程全部作业（控制台是可信界面，
  且在 `admin.require_login` 之下）。
