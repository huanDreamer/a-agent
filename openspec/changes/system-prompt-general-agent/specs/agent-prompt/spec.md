# agent-prompt

## 目标

huan-agent 发给模型的 system prompt 必须有**一个出处**，必须是**中文**，必须**按界面**说清
这个界面能做什么、不能做什么，并且**长度有预算** —— 因为循环内压缩会逐字保留它，它是每一轮
每一步的成本，而不是一次性的开销。

## API

- `prompt.Base() string` —— 与界面无关的基础提示词。
- `prompt.For(surface string) string` —— 基础提示词 + 该界面的段落；未知/空的 surface 返回
  基础提示词本身（不是错误，也不是空串）。
- `prompt.Effective(override, surface string) string` —— `override` 非空白时返回它（去掉首尾
  空白），否则返回 `For(surface)`。
- `prompt.SurfaceWeb` / `prompt.SurfaceCLI` / `prompt.SurfaceFeishu` —— 界面名常量，
  `For` 对大小写与首尾空白不敏感。
- 文本由 `go:embed` 从同目录的 `base.md`、`surface_*.md` 读入：提示词是散文，改它的频率远高于
  改代码，`.md` 让它保持可读（Go 的 raw string 连反引号都放不下）。

## 行为

- **基础提示词 MUST 覆盖五件事**：身份（通用 Agent，把事做完而不只是回答）、语言与表达
  （默认中文、跟随用户语言、直接给结果、Markdown、诚实优先于好看）、做事方式（先查证再动手、
  探索适可而止、一次做完、改动小而准、做完验证、失败说清楚）、工具使用（工具列表即能力边界、
  各工具的选择、`edit_file` 的唯一匹配、非交互命令、后台进程、输出截断、破坏性操作、附件、
  技能）、边界与安全（工作区限制、密钥不外泄、不绕过拒绝、动手前说一句、收尾报告）。
- **无终端规则 MUST 同时给出出路**：命令的标准输入是 `/dev/null`，所以提示词必须写明这一点，
  并给出可用的非交互开关（`-y` / `--yes`、`--no-input`、`CI=1`、`git commit -m`）或管道喂答案。
  只写「不要用交互式命令」是不够的：模型需要知道那类命令在这套工具里长什么样。
- **界面段落 MUST 写明该界面没有什么**：`ask_user` 只在 Web 控制台注册（`Surface == "web"`），
  飞书与 CLI 的段落必须说明这一点并给出替代做法（直接在回答里问）；飞书段落必须说明超宽表格
  会被拆成多条消息；CLI 段落必须说明输出是纯文本、不依赖渲染。
- **覆盖 MUST 是替换而非追加**：`Effective` 返回运维的提示词时，界面段落一并消失 —— 追加一段
  关于卡片与表格的说明，是对运维自己写下的提示词的二次猜测。
- **空白 MUST 等于没填**：全空白/换行的 `override` 走默认提示词。空字符串的系统消息会让模型
  没有任何规则，而配置文件里的空字段的本意是「我不改」。
- **三个界面 MUST 用同一条覆盖规则**：Web 控制台与飞书机器人共用 `chat.system_prompt`，
  二者不得各自实现一遍优先级。
- **提示词 MUST 是中文**：工具描述、技能段落、控制台界面都是中文，两种语言的规则并存只会让
  模型犹豫听谁的。ASCII 在工具名、路径、命令行开关里是正常的，英文散文不是。
- **长度 MUST 有测试守住**：任意界面的提示词不得超过 12 KiB（当前基础提示词约 5 KiB）。
  压缩逐字保留 system 提示，所以它的成本是「体积 × 步数」。
- **变更 MUST 同步工具名**：提示词里出现的每个工具名都必须与注册表一致；模型不会调用它没听说
  过的工具，却会调用提示词里写着、注册表里没有的工具（那是一次必然失败的调用）。

## 接入

- `internal/prompt`（文本 + 拼装）← `internal/server`（控制台：`chatPrompt()`、
  `systemPrompt()` 再拼技能段落）← `web/src`。
- `internal/prompt` ← `cmd/huan-agent`（`serve.go` 的飞书机器人、`chat.go` 的 CLI）。
- 技能的**可用技能**段落不在这个包里：它由 `internal/server/skilltool.go` 每轮拼在系统提示后，
  因为「哪些技能启用」是数据库状态，不是编译进二进制的文本。飞书没有技能面板，因此不拼。

## 不做

- 不做运行时（数据库）可改的提示词：它不随会话变化，改它就该走配置与重启。
- 不做按会话/按用户的提示词：个人 Agent 里没有这个需求，而它会让「这个部署到底在按什么规则
  说话」变成一个要查库才能回答的问题。
- 不做多语言切换：提示词是中文，回答语言由提示词里的「跟随用户的语言」处理。
- 不把单个工具的使用细则写进系统提示词：那些属于工具描述（每次请求都带，且只带被注册的），
  系统提示只放跨工具的行为准则。
