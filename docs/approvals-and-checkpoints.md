# 审批与检查点

这两件事是同一个目的的两半：让人敢把写权限交出去。审批挡住的是**还没发生的**坏决定，
检查点收拾的是**已经发生的**。

## 审批闸门

写/执行类工具调用落地之前，先问一句。

```
需要确认：执行: git push origin main
  完整命令：git push origin main
  工作目录：/srv/app
允许这一次 / 本轮都允许 / 拒绝？[y/t/n，或直接写拒绝理由]
```

### 为什么默认是关的

`tools.approval.mode` 默认 `off`。这不是没做完，是刻意的：默认打开会从**没人在看**的部署
（CI、cron、飞书机器人）手里拿走写权限，那个意外比没有闸门更糟。打开它是一次显式的决定。

### 打开之后各 surface 的行为

| surface | 能不能问 | 结果 |
|---|---|---|
| Web 控制台 | 能（卡片） | 写/执行前弹卡片 |
| 交互式 CLI | 能（终端） | 写/执行前提示，读 y / t / n |
| 飞书 | 不能（本阶段没有卡片） | **不注册**写与执行工具 |
| `huan-agent run` | 不能（无人值守） | **不注册**写与执行工具 |

"不注册"而不是"每次都拒绝"：一个必然失败的工具比不在菜单上的工具更糟，模型会调用它并把
一轮浪费在失败上。启动日志里会写明是哪个 surface、mode 是什么、少了哪些工具。

### 超时是拒绝

这是它与 `ask_user` 最关键的区别，写在两个包的注释里，因为它太容易做反：

| | 没人回答时 |
|---|---|
| `ask_user` | 超时是一种合法答案：模型拿到"用户没回答"，自己收口 |
| 审批 | **拒绝**。没人在看的时候，恰恰是闸门必须生效的时候 |

人工拒绝会带上理由，理由作为工具结果回到模型那里，让它换个做法：

```
该操作已被拒绝，没有执行：执行: git push origin main。
拒绝理由：不要动主分支
请改用在被拒绝的范围内可以完成的做法，或者把需要人确认的部分留在回答里说明；不要重复同一个请求。
```

### 粒度只有两种

`allow_once`（这一次）和 `allow_turn`（本轮内该工具免问）。没有"永久允许"：一次点击变成
一条不再被复查的规则，需要它自己的管理界面，那是另一件事。`allow_turn` 记在轮次的 context
上，所以轮次一结束它就没了。

`tools.approval.allow` 是一份按动作摘要匹配的正则白名单，命中即免问。**它是减速带不是边界**
（与 `tools.deny_patterns` 同一句话），但方向相反：这里默认是"问"，所以漏一条的代价是一次
询问，而不是一次事故。写坏的正则不会变成"全部放行"——解析失败就照常询问。

### 卡片上会显示什么

每类工具的动作摘要不一样，因为一句"模型想调用 edit_file"等于让人批准一件看不见的事：

| 工具 | 摘要 | 预览 |
|---|---|---|
| `bash` / `bash_background` | `执行: <完整命令行>` | **完整命令**（命令行本身永不截断）、工作目录、超时 |
| `write_file` | `写入 <path>（N 行，M 字节，整文件覆盖）` | 新内容的前若干行 |
| `edit_file` | `编辑 <path>（+N 行）` | 删掉什么、换成什么 |
| 其它 | `调用 <工具名>` | 参数 |

`bash` 的命令行**必须完整**：截断会把一条长管道末尾的 `rm -rf` 藏起来，而那正是这套机制
存在的唯一理由。

## 检查点

一轮里被文件工具改过的文件，在改动**之前**留下副本。任何时候可以把这一轮整体回退。

```
/checkpoints
本次会话有 1 个检查点：
  第 1 轮：1 个文件（2026-09-18T01:17:34+08:00）

/rollback 1
已恢复 1 个文件，删除 0 个本轮新建的文件，0 个文件本来就一致
这次回退本身也可以撤销：/rollback 2
```

### 为什么是"改动之前"，而不是"轮次开始时"

轮次开始时**不知道**哪些文件会被改。所以前像是在第一次改动某个文件之前取的
（copy-on-write），而且同一轮里第二次改同一个文件**不会**覆盖第一次的前像——第一次的那份
才是这一轮开始时的样子。

### 三件让它敢被点的事

1. **回退本身可以撤销。** 恢复之前先把当前状态存一份，所以"回退"也是一次回退之外的地方。
   一个单向的破坏性操作不该被做成按钮。
2. **默认不覆盖更新的工作。** 如果文件在这一轮之后又被改过，默认**不覆盖**并列出冲突。
   怎么区分"这一轮改的"和"之后被改的"？每次写入成功后记录写入结果的哈希，所以：
   - 内容 == 本轮最后写入的 → 是本轮自己的改动，直接恢复；
   - 内容两者都不等 → 是别人的改动，拒绝并要求 `--force`。

   这个区分不是理论上的细节：没有它，最常见的情况（"模型刚改的，我想撤掉"）每次都要加
   `--force`，而一个总要加确认标志的操作会训练人闭眼加。
3. **逐文件原子写入。** 临时文件 + rename，中断的回退不会留下半个源文件。

### 覆盖范围，以及不覆盖什么

**覆盖**：通过 `write_file` / `edit_file`（以及将来的 `apply_patch`）的改动。

**不覆盖**：`bash` 造成的改动。一条 `rm -rf` 或 `sed -i` 绕过文件工具直接改盘，要覆盖它就得整仓
快照，成本与收益不成比例。作为补偿，检查点记录轮次开始与结束时的 `git status --porcelain`，
所以"bash 到底动了什么"仍然看得见。**这一点必须让使用者知道**——以为回退能救回一切，比没有
回退更危险。

不在覆盖范围内的条目（目录、超大文件、读取失败）会被**记录并列表显示**，不会静默消失。

### 保留与淘汰

`keep_turns`（默认 20 轮）与 `max_total_mb`（默认 512）双重上限，超出时从最旧的开始淘汰并写日志。
淘汰发生在轮次结束时（目录刚长大的时刻），不是定时器。

### 位置

`tools.checkpoint.dir`，缺省是数据库文件旁的 `checkpoints/` 目录。放在那里而不是工作区里，
理由与后台进程日志相同：落进仓库的检查点会出现在模型自己的 grep 结果里，也会出现在用户的
`git status` 里。

## 相关的配置

```yaml
tools:
  approval:
    mode: "off"            # off | writes | writes+exec | all
    allow: []              # 按动作摘要匹配的正则；命中免问
    timeout_seconds: 300   # 超时=拒绝
  checkpoint:
    enable: true
    dir: ""                # 空 = 数据库文件旁的 checkpoints/
    keep_turns: 20
    max_total_mb: 512
```

## 控制台里的审批卡片

`mode` 非 `off` 时，Web 控制台在**输入框正上方**显示卡片：动作摘要、预览（命令行 / diff /
文件清单）、三个按钮（允许一次 / 本轮都允许 / 拒绝），以及一个"多久之后按拒绝处理"的倒计时。
拒绝时可以写理由，理由会作为工具结果回到模型。

卡片贴在输入框上方而不是消息流里，理由与任务看板相同：这一轮**正卡在这个决定上**，所以它属于
读者正在看的位置；一个需要滚动的决定会拖慢这一轮。

已决定的卡片就地变成一行结论（"允许一次" / "拒绝：不要动主分支" / "拒绝（等待超时，没有人回应）"），
按钮消失。**决定一旦做出就不能翻转**：晚到的点击会得到 404，而不是改变结果。

这张卡片只存在于**运行中的那一轮**。刷新之后看到的是工具卡片与它的结果——因为审批发生在工具调用
**之前**，服务器没有把它存成一条工具调用。这是有意的：回看时该看到的是"问了什么、结果如何"，
而不是一个已经不能再点的卡片。

## 排障

- **`mode` 开了之后 CLI 里没有写工具了** —— stdin 不是终端（管道、重定向），没有可以询问的
  地方，所以按"飞书 / run"那一档处理。日志里有一条说明。
- **飞书机器人突然不能写文件了** —— 同上：它没有审批卡片，闸门开了之后写/执行工具不再注册。
  把 `mode` 设回 `off`，或者只在 Web 面用这个能力。
- **回退报告"这一轮之后文件又被改过"** —— 文件在检查点之后被改动，且不是本轮写入的内容。
  确认要覆盖就加 `--force`；不知道是什么改的就先看 `git status`。
- **回退说某个文件"不在检查点覆盖范围内"** —— 它当时是目录、超过 32 MiB，或读取失败。回退
  不会碰它，报告里列出来了。
- **`/checkpoints` 说"还没有检查点"** —— 这一轮没有通过文件工具改过文件。bash 的改动不算。
- **CLI 里 `/rollback` 找不到上一轮** —— CLI 的会话 id 每次启动都是新的，所以检查点属于**本次
  进程的这次会话**。进程内改完发现不对，立刻回退；跨进程的回退属于控制台（会话 id 持久）。
