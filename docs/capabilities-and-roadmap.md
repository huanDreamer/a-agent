# 大模型能力现状与规划

> 口径说明：**行业部分**为公开信息的汇总，未自行跑过评测，数字当量级参考；**项目部分**为本机实测，附核实命令。
> 本文写于 2026-09，模型迭代很快，具体数值请以当下为准。

---

## 一、行业侧：六项能力的水位

| 能力 | 现状 | 主要瓶颈 |
| --- | --- | --- |
| 长上下文 | 百万级 token 已是旗舰标配 | "放得下" ≠ "用得上"，有效利用率随长度明显衰减 |
| 原生多模态 | 图像理解成熟可用 | 视频、音频的实时交互仍在早期 |
| 推理 | 思维链 + 测试时计算成为标准范式，数学/代码提升显著 | 长链推理的稳定性与成本，链越长越难控 |
| 工具调用 / Agent | 单步调用已可靠 | 多步长任务的成功率是主要矛盾——错误逐步累积 |
| 编码 | 日常任务接近可用，补全和单文件改写体验好 | 跨文件大改、长期维护仍需人盯 |
| 成本 | 单位 token 价格持续快速下降 | Agent 场景 token 消耗随步数放大，总成本未同步下降 |

**一句话**：能力上限还在涨，但落地卡点已经从"能不能"转移到"稳不稳、贵不贵"。

---

## 二、还没解决的事（演进方向）

1. **上下文：从「更长」转向「更有选择」**
   单纯堆窗口收益递减。检索、压缩、分层记忆——决定"哪段该进上下文"——是更实际的方向。

2. **Agentic 的瓶颈是可靠性，不是能力上限**
   单步正确率 95% 听起来不错，二十步之后就只剩 36%。错误恢复、状态校验、可中断重试比提升单步智商更值钱。

3. **速度指标首次进入选型表**
   首 token 延迟和吞吐量开始和大 benchmark 并列出现——用户能感知到的是等待，不是分数。

4. **协议在收敛，治理没跟上**
   工具/上下文协议（如 MCP 一类）逐步统一，但权限边界、审计日志、敏感操作的确认机制仍是各处自建。

## 三、本项目现状（实测）

- **模型目录**：72 个模型条目，但实际接入的供应商只有 1 个在用——登记量远大于可用量。
- **能力标记的来源不可全信**：`capabilities_source='asked'`（真正探测/询问得到）的记录为 9 条。其余标记走的是 `llm.InferCapabilities(info.ID)`——**从模型名猜**（名字含 `gemini`、`vision` 就加 vision），而且这条推断路径不写 `capabilities_source`。所以那张能力表的"来源"列不能当可信度指标用。
- **openspec 任务**：约 1500 项，已完成约 1400 项，剩余散落在若干变更里。

核实方式：

```bash
sqlite3 data/huan-agent.db "select count(*) from llm_models;"
sqlite3 data/huan-agent.db "select capabilities_source, count(*) from llm_models group by 1;"
grep -rn "InferCapabilities" internal/
grep -c "^- \[x\]" openspec/*/tasks.md
```

## 四、未完成事项（规划）

| 事项 | 现状 | 待办 | 核实方式 |
| --- | --- | --- | --- |
| 能力探测补全 | 多数模型靠名字猜能力 | 接入真实探测/询问，并统一写入 `capabilities_source` | 上表 SQL |
| `inferred` 标记落地 | `ModelCapabilitySourceInferred` 已定义但无写入方 | 推断路径补写标记，让来源可区分 | `grep -rn "CapabilitySourceInferred" internal/` |
| 供应商接入 | 已登记 72、在用的少 | 打通实际可用链路，剔除登记即结束的条目 | 供应商状态查询 |
| 上下文有效的选择策略 | 目前是整段塞入 | 检索 + 压缩 + 分层，按需取用 | 有对应测试覆盖 |
| Agent 长任务可靠性 | 单步可靠，多步会累积错误 | 错误恢复、状态校验、中途确认点 | 端到端任务成功率 |
| 成本可见性 | 无按会话/任务的成本口径 | 统计 token 与费用，暴露到界面 | 成本统计接口 |
| 速度指标 | 未采集 | 采集首 token 延迟与吞吐 | 同上 |
| openspec 收尾 | 约 100 项未完成 | 按变更逐项推进或明确废弃 | `grep -c "^- \[ \]" openspec/*/tasks.md` |

## 五、怎么读这份文档

- 行业部分的数字**不要当精确值**：同一个模型的上下文窗口，不同来源能差一个数量级。趋势在多个来源里一致，绝对值不可全信。
- 项目部分是实测的，但**会随代码变化**——本文提到的问题（推断路径不写来源）如果已被修掉，请以代码为准。
